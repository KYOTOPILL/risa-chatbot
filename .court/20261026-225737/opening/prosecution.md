**Charge: the fix is not sound as built and should not be committed as described.**

1. **The headline change is untested where it matters.** The case says: "With only one topic folder today, the category filter has no practical effect yet" and that multi-topic behaviour "was not tested with real multi-topic data." The only evidence is "a unit test with a fake store." Every passing live result (receipts, thesis, announcement) comes from the one-folder setup, so those results say nothing about the filter. Cost: the team ships an untested core mechanism and reads the 7-file results as proof that it works.

2. **A wrong category guess hurts exactly when it is wrong.** The case admits "The model's category guess is sometimes wrong." The fallback only fires "if nothing there is under NAME_MAX". If the guessed folder holds a weak match that scores under 0.45, the search returns it and never looks elsewhere. A wrong guess therefore produces a wrong file, not a miss. With 6 near-identical receipts in one folder, a weak same-folder hit is the likely result. Cost: the wrong document goes out to staff, and no error is logged.

3. **The thresholds were tuned on 7 files and will not scale to 500.** "Both thresholds were tuned on these 7 files only." Even at 7 files, "ขอไฟล์ทั้งหมดของทุน CMU" lost one file that was "just outside NAME_MAX". NAME_TIE 0.03 also sends every file in a tie. With 500 files and many near-identical forms per topic, ties will return large unwanted bundles, and valid files will fall below the cutoff. Cost: retuning blind, or silent misses and over-sending.

Cost: an ongoing list of patches and false file replies.

Cost: regressions cannot be detected, and the index rebuild required by any format change repeats the cost and the risk.
